# Isolated AppleScript workers

Run `./WorkerIntegrationTests/run.sh /absolute/path/to/MTMR.app/Contents/Helpers/MTMRScriptWorker` after building the app. The tests exercise persistent script properties, text/list/file results, concurrent workers, timeouts, recovery/backoff, Automation denial, busy CPU termination, low-CPU waits, early closure of pipes and worker cleanup. `./ActionRunnerTests/run.sh` verifies queued tap actions return without blocking and execute in order. `python3 WorkerIntegrationTests/parent_death.py /absolute/path/to/MTMRScriptWorker` checks that a stuck helper exits after its parent is forcibly stopped.

The worker is built into Contents/Helpers by the Xcode build phase. Signing a distributable application must also sign this nested executable; the build script signs it when Xcode supplies a signing identity. Tests use synthetic data and do not prove that macOS attributes Automation permission to this helper as intended. A locally signed build may require permission again for Spotify or System Events. The first or any later Apple Event can trigger a permission dialog; a request is allowed up to 30 seconds, and a worker is terminated if a single request consumes over five seconds of CPU time. A failure retries with exponential backoff of up to 60 seconds. Explicit Automation denial stops retries until restart. A legitimate, computationally expensive script can also exceed the CPU budget and be stopped. These behaviors require real-device validation.
